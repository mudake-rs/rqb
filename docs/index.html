Postgres-only Rust query builder on top of sqlx. rqb validates typed query shapes, renders parameterized SQL, and stays out of ORM territory.

rqb(7)                  Rust/Postgres Query Builder                  rqb(7)

NAME
     rqb - typed Postgres query construction and sqlx execution helpers

SYNOPSIS
     Rust owns query shape.  User values become Postgres bind parameters.
     JSON search can filter and sort only fields exposed by metadata.

What It Is

rqb is a library for service code that wants to build Postgres queries in Rust without becoming an ORM. It models tables, fields, expressions, writes, CTEs, joins, locks, and JSON search boundaries. It validates the shape before SQL rendering and executes through sqlx Postgres executors.

rqb does

  • render parameterized Postgres SQL with $N placeholders;
  • bind Rust values through sqlx, not string interpolation;
  • validate field/operator/query-shape mistakes before rendering;
  • generate compact schema metadata from Postgres;
  • let server code own joins, CTEs, writes, raw SQL, and locks;
  • let client JSON control only safe search fields.

rqb does not

  • hide the Postgres dialect;
  • define database migrations;
  • generate row models or entity graphs;
  • turn HTTP JSON into arbitrary SQL;
  • try to prove the whole SQL program at compile time;
  • support non-Postgres backends.

Install

[dependencies]
rqb = "0.1.2"
sqlx = { version = "0.9.0", features = [
    "postgres",
    "derive",
    "uuid",
    "chrono",
    "json",
    "runtime-tokio",
    "tls-rustls",
] }

Install the schema generator when you want to introspect a live database:

cargo install rqb-cli

Small Query

use rqb::prelude::*;
use uuid::Uuid;

rqb::schema! {
    table public.app_users {
        id: uuid = Uuid,
        email: text = String,
        status: text = String,
    }
}

let query = select(app_users::table())
    .columns((app_users::ID, app_users::EMAIL))
    .filter(app_users::STATUS.eq("active"))
    .order_asc(app_users::EMAIL)
    .limit(20)
    .build()?;

println!("{}", query.pretty());

The built query contains SQL with placeholders, ordered bind parameters, and cacheability metadata. query.pretty() is for logs and does not interpolate values into SQL.

Core Model

Part Owner Meaning
Schema metadata Server Fields, Postgres types, operator capabilities, JSON visibility.
Query shape Server Rust code Sources, joins, projection, CTEs, writes, locks, raw fragments.
Values Application or request Bound through sqlx as Postgres parameters.
JSON search Client, inside metadata limits Filter, sort, limit, and offset over exposed fields only.
